Статус: утверждённый дизайн, готов к имплементации.

Этот документ — техническое задание для имплементации. Все упомянутые

## 1. Цели

- Заменить временный бинарный QDataStream-формат (`fml_file_buffer.h`) и
  заглушки `load_fml`/`save_fml` (`src/fileio.cpp:80-99`) на постоянный
  формат: **zip-контейнер с `manifest.json` и отдельными файлами картинок**.
- Сохранить семантику данных, уже принятую в кодовой базе (порт beeref):
  элементы с полями `type, x, y, z, scale, rotation, flip, data` —
  см. схему beeref (`beeref/fileio/schema.py`) и потребителя
  `CanvasScene::add_queued_items()` (`src/canvasscene.cpp:971`).
- Загрузка/сохранение в фоновом потоке через существующий `ThreadedIO`
  (`src/fileio.h:31`) с прогрессом и отменой.
- Эволюция формата без ручного версионирования блоков: новые поля JSON
  старый код игнорирует; неизвестный `type` → `ErrorItem` (уже реализовано
  в `add_queued_items`).

## 3. Контейнер и библиотека

**Контейнер:** обычный zip. Переименовал в `.zip` — открыл и прочитал глазами.

**Библиотека: miniz, вендорится в `include/miniz/`** — по той же схеме, что
уже вендорены `include/quill` и `include/kColorPicker`
(`CMakeLists.txt:53-57`). Причины выбора:

- KArchive (KZip) отвергнут: тянет KDE Frameworks — неприемлемая
  зависимость для маленького проекта, собирающегося и под MSVC
  (см. недавние коммиты "MSVC try fix").
- QZipWriter/QZipReader отвергнуты: приватные заголовки Qt, ломаются при
  смене версии Qt.
- miniz: 1-2 файла (`miniz.h`/`miniz.c`), лицензия MIT, компилируется как C
  везде, включая MSVC.

Имплементатору: взять последний релиз miniz с
https://github.com/richgel999/miniz, положить в `include/miniz/`,
подключить в `src/CMakeLists.txt` (компилировать `miniz.c` как часть
таргета или отдельной статической библиотекой — на усмотрение).

**Параметры записи:**
- `manifest.json` — с компрессией (deflate, дефолтный уровень).
- `images/*` — **без компрессии** (store): PNG/JPG уже сжаты, deflate
  поверх них тратит CPU впустую и мешает быстрому чтению.

## 4. Структура архива

```
project.fml  (zip)
├── manifest.json          — вся структура сцены
└── images/
    ├── <uid>.png          — имя = uid элемента (§5.1), формат из get_imgformat()
    ├── <uid>.jpg
    └── ...
```

Правила:
- Пути внутри архива — только ASCII, прямые слэши, без ведущего `/`.
- Имя файла картинки: `images/<uid>.<ext>`, где `uid` — постоянный UUID
  элемента (§5.1), `<ext>` — формат из `get_imgformat()`. Стабильное имя
  между сохранениями: неизменённый элемент даёт идентичный entry — задел
  под инкрементальную перезапись (§13).
- Файлов, на которые не ссылается manifest, в архиве быть не должно
  (при полной перезаписи это выполняется автоматически).

## 5. Схема `manifest.json` (formatVersion = 1)

```json
{
  "format": "familiar",
  "formatVersion": 1,
  "appVersion": "0.1.0",
  "scene": {},
  "items": [
    {
      "id": "9f1c2d34-5a6b-4c7d-8e9f-0a1b2c3d4e5f",
      "type": "pixmap",
      "x": -120.5,
      "y": 40.0,
      "z": 0.31,
      "scale": 1.0,
      "rotation": 0.0,
      "flip": 1,
      "image": "images/9f1c2d34-5a6b-4c7d-8e9f-0a1b2c3d4e5f.png",
      "data": {
        "filename": "cat.jpg",
        "opacity": 1.0,
        "grayscale": false,
        "crop": [0, 0, 800, 600]
      }
    },
    {
      "id": "2b7e1512-28ae-4d2a-abf7-158809cf4f3c",
      "type": "text",
      "x": 10.0,
      "y": 20.0,
      "z": 0.32,
      "scale": 1.5,
      "rotation": 0.0,
      "flip": 1,
      "data": { "text": "Заметка" }
    }
  ]
}
```

Пояснения по полям:

| Поле | Откуда берётся | Примечание |
|---|---|---|
| `format` | константа `"familiar"` | опознавательный маркер; проверять при загрузке |
| `formatVersion` | константа `1` | целое; политика в §6 |
| `appVersion` | версия приложения из CMake | только диагностика, на логику не влияет |
| `scene` | пока пустой объект | зарезервировано под настройки сцены (цвет фона и т.п.) |
| `items[].id` | постоянный UUID элемента (§5.1) | строка, lowercase, без фигурных скобок; имя картинки в архиве |
| `items[].type` | `IBaseItem::get_type()` | `"pixmap"` / `"text"`; новые типы — просто новые значения |
| `x, y, z, scale, rotation, flip` | общие свойства `QGraphicsItem` + `flip()` | ровно те же шесть полей, что в схеме beeref; `flip` ∈ {1, -1} |
| `image` | только у `pixmap` | путь внутри архива |
| `data` | `get_extra_save_data()` элемента | типо-специфичный словарь; ключи см. `src/moveitem.h:217` (pixmap) и `src/moveitem.h:801` (text) |

Замечание про `crop`: беречь порядок `[x, y, w, h]` — ровно так его пишет
`PixmapItem::get_extra_save_data()` и читает `add_queued_items()`.

### 5.1. Идентичность элементов: постоянный UUID вместо save_id

В beeref `save_id` — это rowid SQLite (`items.id INTEGER PRIMARY KEY`),
нужный для инкрементального UPDATE/DELETE строк; у нового элемента его
нет до первого INSERT — отсюда `std::optional` и вся машинерия
`has_save_id()/clear_save_ids()`. В zip-формате с полной перезаписью эта
модель не нужна. Вместо неё:

- У каждого элемента постоянный `QUuid uid_`, генерируемый **один раз в
  конструкторе** (`QUuid::createUuid()`). Никогда не пустой, никогда не
  сбрасывается, никакой перенумерации при сохранении.
- Сериализация: `uid_.toString(QUuid::WithoutBraces)` — lowercase, без
  скобок; это же значение — имя картинки в архиве.
- **Загрузка**: uid восстанавливается из файла. Отсутствует или
  дублируется в пределах одного manifest (= повреждённый файл) —
  залогировать warning и сгенерировать новый; не падать.
- **Копирование — критичное правило**: `create_copy()` и любой будущий
  paste/duplicate ВСЕГДА генерируют новый uid (т.е. конструктор копии
  делает это сам; uid не входит в копируемые свойства). Единственное
  место, где uuid можно случайно растиражировать.
- **ErrorItem** сохраняет uid оригинального элемента (поле
  `original_save_id` в `src/moveitem.h:918` переименовывается в
  `original_uid`, тип `QUuid`) — round-trip через старую версию
  приложения не меняет идентичность элемента.
- Изменение интерфейса `IBaseItem`: методы
  `has_save_id()/get_save_id()/set_save_id()/clear_save_id()` и
  `CanvasScene::clear_save_ids()` (`src/canvasscene.cpp:861`) удаляются;
  вместо них `QUuid uid() const` + `void set_uid(const QUuid&)`
  (set — только для восстановления при загрузке).
- `get_filename_for_export()` (`src/moveitem.h:231`) переводится с
  `save_id` на uid либо на порядковый номер, формируемый на месте, — на
  усмотрение имплементатора (функция и так помечена TODOLATER).

Мотивация стабильного uid, помимо упрощения: неизменённый элемент даёт
идентичный entry картинки между сохранениями (задел под инкрементальную
перезапись и меньшие диффы, §13) и стабильные ссылки на элементы для
будущей группировки (группа ссылается на детей по uid).

## 6. Версионирование и совместимость

- **Незнакомое поле JSON** — молча игнорировать (и при чтении, и значит
  добавление полей не требует bump-а версии).
- **Незнакомый `type`** — создать `ErrorItem` с сообщением (уже реализовано
  в `add_queued_items`). TODOLATER (уже помечен в `src/moveitem.h:966`):
  сохранять исходный JSON элемента внутри `ErrorItem` и записывать его
  обратно при сохранении, чтобы файл от новой версии не терял данные при
  редактировании в старой. В v1 достаточно видимого плейсхолдера.
- **`formatVersion` больше поддерживаемого** — отказ загрузки с внятной
  ошибкой ("файл создан более новой версией familiar").
- **Bump `formatVersion`** — только при несовместимом изменении семантики
  существующих полей (не при добавлении новых). Миграции — по образцу
  beeref `MIGRATIONS`: словарь `{версия: функция-преобразование JSON}`.
- **Опознание файла**: zip начинается с байтов `PK\x03\x04`. Если файл
  `.fml` не начинается с них — это легаси-формат (§10) или мусор.
- **Magic number для content-based детекта (добавлено позже, см. ниже)**:
  первым entry в архиве — `mimetype` (store, без extra field), содержимое
  — буквально `application/x-familiar-fml`. Тот же приём, что у ODF/EPUB
  (проверено по их реальным записям в shared-mime-info) — фиксирует
  содержимое на оффсете 38 (имя `mimetype` — на 30), что даёт
  `file`/libmagic-детект и позволяет добавить `<magic>`-блок в mime-XML
  (`packaging/linux/org.tryhardfactory.Familiar.xml`) в дополнение к
  `<glob>`. **Не про иконку на ОС** — она уже полностью работает через
  расширение (реестр на Windows, UTType на macOS, `<glob>` на Linux),
  content-sniffing тут ни при чём; это чисто для инструментов, которые
  смотрят на байты, а не на имя файла (`file project.fml` теперь скажет
  осмысленный mime-type вместо голого "Zip archive"). Чисто аддитивно —
  старые ридеры (включая `FmlArchive::load()`, который эту запись вообще
  не ищет) просто её игнорируют, `formatVersion` бампать не нужно.

## 7. Архитектура кода

Новый модуль: `src/fml_archive.h` / `src/fml_archive.cpp`. Синхронное
ядро без знания о потоках и диалогах:

```cpp
// Результат операции; error.isEmpty() == успех.
struct FmlResult {
    QString error;          // фатальная ошибка (файл не читается и т.п.)
    QStringList itemErrors; // нефатальные (одна картинка не декодировалась)
};

class FmlArchive {
public:
    // Сцена -> zip-байты в памяти. progress/canceled опциональны.
    static FmlResult save(CanvasScene* scene, const QString& filename,
                          ThreadedIO* worker = nullptr);

    // zip-файл -> очередь scene->add_item_later(...).
    // НЕ трогает QGraphicsScene напрямую (только mutex-очередь) —
    // безопасно из фонового потока, как load_images (src/fileio.cpp:29).
    static FmlResult load(const QString& filename, CanvasScene* scene,
                          ThreadedIO* worker = nullptr);
};
```

`load_fml`/`save_fml` в `src/fileio.cpp` превращаются в тонкие обёртки над
`FmlArchive`, эмитящие `worker->finished(...)` — их сигнатуры уже
согласованы с beeref и менять их не нужно.

### 7.1. Изоляция JSON-библиотеки (требование)

Qt-JSON-типы (`QJsonDocument`, `QJsonObject`, `QJsonArray`, `QJsonValue`)
**не покидают `fml_archive.cpp`** — ни в заголовках, ни в сигнатурах,
ни в остальном коде. Манифест внутри модуля представляется плоскими
DTO-структурами:

```cpp
struct ManifestItem {
    QUuid id;
    QString type;
    qreal x, y, z, scale, rotation;
    int flip;
    QString image;          // пусто для не-pixmap
    QVariantMap data;       // типо-специфика (crop, text, ...)
};

struct Manifest {
    int formatVersion;
    QString appVersion;
    QList<ManifestItem> items;
};
```

Единственные две точки контакта с JSON-библиотекой — две свободные
функции в `fml_archive.cpp`:

```cpp
std::optional<Manifest> parse_manifest(const QByteArray& json, QString& error);
QByteArray write_manifest(const Manifest& m);
```

Обоснование: это «шов» для возможной замены QJson на другой парсер —
замена сводится к переписыванию тел этих двух функций в одной единице
трансляции. Темплейтная/виртуальная обёртка над JSON-API отвергнута
сознательно: DOM- и on-demand-парсеры не изоморфны по API, общая
абстракция получается протекающей и съедает выигрыш быстрых бэкендов.
Ключи `data` остаются схемо-свободным `QVariantMap` — он в этом же виде
уходит в `add_queued_items()`.

Доступ к данным элементов: у `IBaseItem` уже есть `get_type()`.
Изменения интерфейса:
- **добавить виртуальный `QVariantMap get_extra_save_data() const`**
  (сейчас объявлен только в конкретных классах `PixmapItem`, `TextItem`);
  `flip()` — проверить наличие в интерфейсе, при отсутствии добавить;
- **заменить машинерию save_id на постоянный uid** — см. §5.1
  (`has_save_id()/get_save_id()/set_save_id()/clear_save_id()` →
  `uid()/set_uid()`).

## 8. Алгоритм сохранения

1. `items = scene->items_for_save()` (возвращает элементы в
   `Qt::AscendingOrder` — стабильный порядок в manifest).
2. Собрать JSON-объект элемента: `id` = `uid()` (§5.1), общие поля +
   `data` из `get_extra_save_data()`.
3. Для `PixmapItem` дополнительно: `pixmap_to_bytes()`
   (`src/moveitem.h:268`, формат выбирает `get_imgformat()`), путь
   `images/<uid>.<ext>` — записать в архив (store, без deflate) и в поле
   `image`. ВАЖНО: `pixmap_to_bytes()` вызывать с дефолтными флагами
   (`apply_grayscale=false, apply_crop=false`) — grayscale и crop это
   отображаемые свойства, оригинал картинки не модифицируется.
4. `manifest.json` — из `QJsonDocument::toJson(QJsonDocument::Indented)`
   (индентация — копейки по размеру после deflate, а отлаживаемость
   глазами была одной из целей формата).
5. **Атомарность**: собрать весь zip в памяти (miniz умеет писать в
   heap-буфер), затем записать через `QSaveFile` + `commit()`. Прерванное
   сохранение не должно уничтожать прошлый файл. Оценка памяти: референс-
   борда на сотни картинок — сотни МБ; для v1 приемлемо, альтернатива
   (temp-файл рядом + rename) — в §12.
6. Прогресс: `worker->beginProcessing(count)` перед циклом,
   `worker->progress(i)` на элемент, `worker->canceled` — прервать и НЕ
   коммитить `QSaveFile`.
7. После успеха вызывающая сторона (`FileActions`) делает
   `setModified(false)`.

## 9. Алгоритм загрузки

1. Открыть zip; если не zip (нет `PK\x03\x04`) — попытка легаси-чтения
   (§10), иначе ошибка.
2. Прочитать и распарсить `manifest.json` (`QJsonDocument::fromJson` с
   `QJsonParseError`). Проверить `format == "familiar"` и
   `formatVersion <= 1`.
3. `worker->beginProcessing(items.size())`.
4. Для каждого элемента manifest-а собрать `QVariantMap` ровно в том виде,
   который ждёт `add_queued_items()` (`src/canvasscene.cpp:988-1060`):
   - `type`, `x`, `y`, `z`, `scale`, `rotation`, `flip` — верхний уровень;
   - `id` (uid из файла) — верхний уровень; `add_queued_items()` дополнить:
     после создания элемента вызвать `set_uid()` (правила восстановления
     и обработки битых uid — §5.1);
   - `data` — вложенный map (`crop`, `text`, …);
   - для `pixmap`: извлечь файл по пути из `image`, декодировать в
     `QImage` (`QImage::fromData`), положить в ключ `image`; `filename` —
     из `data.filename`. Картинка не декодировалась → в `itemErrors`,
     элемент пропустить (или ErrorItem — на усмотрение, beeref добавляет
     ErrorItem).
   - `scene->add_item_later(map, /*selected=*/false)`.
5. `worker->progress(i)` на элемент; уважать `worker->canceled`.
6. `worker->finished(error, itemErrors)`; GUI-поток дренирует очередь
   `add_queued_items()` по сигналу — по образцу
   `CanvasView::do_insert_images` (упомянут в `src/fileio.h:72`).

Примечание: в отличие от beeref (где save_id — rowid SQLite,
присваиваемый после INSERT), uid здесь — постоянное свойство элемента:
он восстанавливается при загрузке и не меняется при сохранениях (§5.1).

## 10. Легаси-формат и уборка

Старый бинарный формат: `qint16 count`, затем на элемент
`QPointF scenePos, qint32 h, w, QRectF br, quint16 format, quint64 size,
qCompress-данные` (`src/fml_file_buffer.h:48-79`).

Решение: **легаси-ридер сохранить на один релиз** как ветку в
`FmlArchive::load` (файл не начинается с `PK\x03\x04` → читать по старой
схеме, элементы конвертировать в те же `QVariantMap` для очереди; ключа
`id` в них не будет — элементы получат свежие uid из конструктора).
Сохранение — всегда только в новый формат: открыл легаси → сохранил →
файл уже zip. Удалить легаси-ридер в фазе 9 roadmap (пасс тестирования)
или при выпуске 1.0.

Уборка после перехода:
- `fml_file_buffer.h/.cpp` удалить; вызовы в `FileActions`
  (`src/file_actions.cpp:83,95-96,138`) перевести на
  `save_fml`/`load_fml`.
- `CanvasScene::fml_payload()` (заглушка, `src/canvasscene.cpp:1115`) и
  `create_payload` удалить — формирование payload переезжает в
  `FmlArchive`.
- `addImage(...)` путь в `CanvasView` (потребитель легаси-ридера) — оставить
  до удаления легаси-ридера, если он больше нигде не используется.

## 11. Интеграция с FileActions и план коммитов

Порядок для имплементатора — 4 коммита, каждый собирается и работает:

**Коммит 1 — miniz + каркас.** Вендоринг `include/miniz`, подключение в
CMake, `fml_archive.h/.cpp` с пустыми `save/load`, юнит вокруг
zip-хелперов (записать/прочитать архив в temp-каталоге). Критерий:
сборка на Linux + существующий MSVC-пайплайн (appveyor) не сломаны.

**Коммит 2 — сохранение.** §8 полностью; `save_fml` → `FmlArchive::save`;
`FileActions::saveFile` вызывает `save_fml` (пока синхронно, без
ThreadedIO — диалоги прогресса подключаются в коммите 4). Критерий:
сохранённый файл переименовывается в `.zip`, открывается архиватором,
`manifest.json` читается глазами, картинки лежат в `images/`.

**Коммит 3 — загрузка + легаси.** §9 и §10; `load_fml` →
`FmlArchive::load`; `FileActions::processOpenFile` вызывает `load_fml`.
Критерий: round-trip (сохранил → открыл → элементы на местах с
pos/z/scale/rotation/flip/crop/text), старый `.fml` открывается через
легаси-ветку.

**Коммит 4 — фоновая обработка.** Обернуть save/load в `ThreadedIO` по
образцу `load_images` + диалог прогресса; отмена не портит файл
(QSaveFile без commit). Удалить `fml_file_buffer`, `fml_payload()`.
Критерий: загрузка борды на ~100 картинок не фризит GUI; отмена работает.

## 12. Тестирование

Тестовой инфраструктуры в проекте нет — минимум для этой фазы:

- Ручной чек-лист round-trip (в PR-описании): pixmap с crop + grayscale +
  rotation + flip, text с кириллицей, пустая сцена, файл с незнакомым
  `type` (руками поправить manifest) → ErrorItem, битый zip → ошибка без
  краха, легаси-файл.
- Если имплементатор поднимет QtTest-таргет — round-trip тест
  `FmlArchive::save`→`load` на синтетической сцене будет первым
  кандидатом; но это не блокер фазы.
